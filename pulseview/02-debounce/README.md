# Debounce (Webinar 2) — логічний аналіз

**Що міститься:** `wokwi.vcd`, скріншоти Surfer з курсорами (png).

**Пояснення по `workwi.vcd` та `surfer 4.png`:** Імпульс був значно довшим за інтервал debounce (1 ms, DEBOUNCE_US = 1000), тому логіка debounce сприйняла його як дійсне натискання. Обмеження: вхід NOISE активувався вручну клацанням миші, що зазвичай генерує імпульси тривалістю від десятків до сотень мілісекунд. Таким способом неможливо відтворити справді короткий шумовий імпульс (коротший за інтервал debounce). Тому цей ручний тест не дозволяє перевірити, чи відбувається відхилення коротких шумових імпульсів.

**Пояснення по скріншотах `surfer 1.png`, `surfer 1.png`, `surfer 3.png`:** Одне фізичне натискання кнопки спричиняє брязкіт контактів на D0 (RAW): було зареєстровано 44 фронти сигналу (переривання). Подібний брязкіт також спостерігається під час відпускання кнопки. На відміну від цього, D1 (LOGICAL) показує лише один чіткий перехід сигналу, тобто одну подію після усунення брязкоту контактів (debouncing). У результаті було згенеровано рівно 1 логічну подію та виконано 1 дію. Це підтверджує, що логіка усунення брязкоту контактів працює правильно.
